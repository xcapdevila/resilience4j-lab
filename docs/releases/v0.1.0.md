# Resilience4j lab v0.1.0

Initial release of the standalone local lab for comparing standard CircuitBreaker
recovery with experimental gradual traffic admission.

## Included

- Java 25 / Spring Boot 4 application, with the pinned custom Resilience4j library
  built separately using Java 21.
- Real HTTP traffic against a synthetic dependency, with configurable demand,
  concurrency, latency, failures and recovery scenarios.
- Recovery controls for traffic steps, phase duration, sample size, independent
  health bands and `OPEN` / `STEP_BACK` strategies.
- Local Docker Compose stack with Prometheus, Grafana, classic state histories and
  gradual target/admission panels.
- Application tests, offline checks and live-stack validation in GitHub Actions.
- Importable dashboard JSON attached to the release, and screenshots in the README.

## Requirements and limits

Follow the README quick start with Git, Python 3.9+, JDKs 21 and 25, and a local Docker
engine with Compose. The first build fetches public dependencies and images.

Gradual recovery is an experimental upstream proposal, not an official Resilience4j
release. The library source is pinned to
`12a8bc6b6487e50af35a25759a20693965616ddf`. Recovery samples keep the existing
completion-time attribution semantics, so earlier-phase calls can contribute to a
later phase. Traffic generation and simulated backend behavior are demonstration
tools, not provider capacity models or performance benchmarks. Keep this stack local;
it includes anonymous Grafana viewing and development credentials.
